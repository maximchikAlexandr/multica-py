# CubeSandbox compatibility spike — unsupported

## Scope and immutable evidence

- Reviewed upstream: [`TencentCloud/CubeSandbox@0f7ab984be668313232fa3136e1a688b46cb558c`](https://github.com/TencentCloud/CubeSandbox/tree/0f7ab984be668313232fa3136e1a688b46cb558c).
- Reviewed public Python SDK version: `0.6.0` from [`sdk/python/pyproject.toml`](https://github.com/TencentCloud/CubeSandbox/blob/0f7ab984be668313232fa3136e1a688b46cb558c/sdk/python/pyproject.toml#L7-L15).
- Method: static review of that pinned public SDK and checked-in CubeProxy routing. No sandbox was created, no image/template was built, and no dependency was added.
- Decision rule: every row is mandatory for `CommandExecutor`; one **FAIL** or **UNKNOWN** means no adapter is proposed and the common contract stays unchanged.

## Actual data plane (confirmed, non-SSH)

`Sandbox.commands.run()` is a synchronous HTTP Connect-JSON call to guest `envd`, not SSH. Its fallback sends `POST http://{49983-sandbox-host}/process.Process/Start` with `application/connect+json`; the host is built from port `49983`. CubeProxy explicitly recognises `process.Process/Start` and `process.Process/Connect` as unbuffered `envd` streaming paths. See [`_commands.py:121-168`](https://github.com/TencentCloud/CubeSandbox/blob/0f7ab984be668313232fa3136e1a688b46cb558c/sdk/python/cubesandbox/_commands.py#L121-L168), [`_commands.py:171-187`](https://github.com/TencentCloud/CubeSandbox/blob/0f7ab984be668313232fa3136e1a688b46cb558c/sdk/python/cubesandbox/_commands.py#L171-L187), and [`CubeProxy/nginx.conf:177-187`](https://github.com/TencentCloud/CubeSandbox/blob/0f7ab984be668313232fa3136e1a688b46cb558c/CubeProxy/nginx.conf#L177-L187).

The Python SDK dynamically imports `e2b.envd.process`, but it is not declared in its project dependencies; this spike therefore does not treat that optional import as a separately pinned, stable SDK contract. See [`_commands.py:81-119`](https://github.com/TencentCloud/CubeSandbox/blob/0f7ab984be668313232fa3136e1a688b46cb558c/sdk/python/cubesandbox/_commands.py#L81-L119) and [`pyproject.toml:7-16`](https://github.com/TencentCloud/CubeSandbox/blob/0f7ab984be668313232fa3136e1a688b46cb558c/sdk/python/pyproject.toml#L7-L16).

## Result

**CubeSandbox is unsupported for the current executor contract.** The blockers are no non-PTY spawn/handle/collection/control, no stdin, generic executable failures, and lossy text result mapping. The shell-only argv surface is additionally unproven.

No `execution/cubesandbox.py`, `multica-py[cubesandbox]` extra, provider dependency, image/template build, production code, or live test is proposed. A future spike can be reopened only with a separately version-pinned, public non-PTY `envd` process API that proves every failed/unknown row; it must not weaken `CommandExecutor`.
